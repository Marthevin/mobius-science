# Proposal editorial review

**Title and abstract:** State the population/system, intervention or phenomenon, core question, design, and intended contribution. Read every quantitative number against `design-result.json`. Do not summarize projected results as achieved results.

**Background and gap:** Every material factual sentence has a nearby source; the source supports that exact claim. Name the unresolved contrast and population. Discuss conflicting or negative evidence and why this study can distinguish explanations. Do not call a missing keyword search a literature gap.

**Innovation:** Separate conceptual, methodological, and application novelty. Check each against recent work; novelty is a comparison, not an adjective. Be willing to say the project is a rigorous replication rather than inventing a first-ever claim.

**Aims and methods:** Each aim has a specific observable outcome, measurement schedule, inclusion criteria, unit of analysis, effect estimand, comparison, bias controls, missing-data strategy, uncertainty interval, and Plan B. The fallback must still test the aim or explicitly change the claim. No post-hoc power claims.

**Feasibility and ethics:** Data/licence/recruitment access, equipment, collaborators, computational demands, consent, privacy, adverse-event procedures, and timeline should be verifiable. Distinguish resources already secured from requests and assumptions.

**Final read:** Test logical continuity from evidence → gap → aim → design → analysis → expected contribution. Look for unsupported causal claims, stale sample sizes, citation drift, excessive jargon, page imbalance, and inconsistent language. Ask a domain expert for content review when high-stakes submission quality matters; an automated pass cannot replace them.

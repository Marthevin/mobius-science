# OpenCode and Notebook runtime boundary

Managed Skill resources can be readable by OpenCode but external to the Notebook sandbox. For an external-path denial, use the app's supported `host.skills.read('literature-deep-review', 'references/evidence-contract.md')` or the corresponding `scripts/evidence.py` path; do not retry arbitrary filesystem routes. Native OpenCode Read may also work in releases with scoped Skill-directory access. `host.skills.read` returns complete file content, not execution permission. Create a complete session-local copy inside the Notebook's writable workspace, compare SHA-256 and byte length, and execute only that local copy. Never use a blocked managed path through `%run`, `subprocess`, `importlib`, or shell as a workaround. Record the source Skill version, session-local file hash, run directory, and final document hash. If transfer or original validation cannot be verified, label the step unavailable or the script as an adaptation.
